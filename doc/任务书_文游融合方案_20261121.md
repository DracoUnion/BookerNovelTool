## 1. 背景与目标

本仓库已按 `任务书_Galgame_20261121.md` 实现 `gal` 子命令：把小说（EPUB/纯文本）离线解构为结构化游戏资产包（`worldbook.json` / `scenes.json` / `initial_state.json` / `manifest.json`），再通过状态化运行时引擎，用 OpenAI API 驱动可交互中文文字游戏。**LLM 只负责生成叙事与抽取结构化信息，世界真实状态由 Python 侧状态机维护，绝不依赖 LLM 记忆。**

本任务书的目标是：**将 `D:\src\novel2gal` 下文游项目的成熟工程实践融入 `gal` 子命令，使其从“最小可运行原型”演进为可生产、可审计、可恢复、可扩展的中文文游叙事引擎。**

**明确界限：只做中文互动文游/文字游戏，不做视频、音频、图文生成等多模态产物。** 长期若引入图像作为可选表现层，图像仅为表现层，不与状态逻辑耦合；严格排除影片/视频/动画/音频相关内容。

## 4. 融合方案（只做中文文游，不做视频）

方案分三个层次，全部围绕“中文文游叙事引擎”展开，不涉及影片/音频/视频组装。

### 4.1 短期：可直接落地到 `gal` 子命令（本周内，零依赖）

| 融入来源 | 改进点 | 在 `gal` 中的具体做法 | 涉及文件 |
|---|---|---|---|
| **AI-Game-From-Story** | 状态与叙事彻底分离；PDVA 建议→校验→生效 | 已实现：`TurnResult` 由 LLM 生成，`GameEngine.apply()` 在 Python 侧硬校验（scene_change 目标必须存在于世界书；item_delta 物品必须在当前地点/背包；relationship 裁剪到 [-1,1]；非法字段丢弃并 warning，修正重试后仍失败降级为仅叙事） | `gal_engine.py` `apply()` |
| **AI-Game-From-Story / rpg-roleplay-platform** | 滚动摘要与记忆预算；可恢复运行时 | 已实现：`assemble_context()` 分层组装；`fold_history_if_needed()` 超预算折叠旧历史并调用 `summarize_history()`；`save.json` 含 `assets_hash`，读档时与 `manifest.json` 校验，不一致拒绝 | `gal_engine.py`、`gal_play.py` |
| **LLM-Interactive-Fiction-Game-Console** | 结构化 JSON 解析失败的纯文本兜底 | `call_llm_structured()` 解析失败时，可尝试 `ext_code_block` 提取，再 `json_repair`；全部失败后由 `gal_engine.apply()` 降级为“仅叙事、不改状态”，不中断游戏 | `openai.py` `call_llm_structured`、`gal_engine.py` |
| **Story-to-game** | 自动化验证与兜底规则 | 新增 `--validate` 验收步骤：对资产包做场景完整性（场景数 ≥ 章节数 × 4）、角色去重、地点连通性等 13 项风格化检查；失败列出清单供人工修复 | `gal_parse.py` 新增 `step_validate_assets()`（或独立 `gal_validate.py`） |
| **rpg-roleplay-platform** | 输入指纹与缓存失效 | 已实现：`source_hash` 作为缓存键与存档版本锚定；`--skip-existing` 命中则 0 次 LLM 调用；上游小说改动后 `source_hash` 变更，缓存自动失效 | `gal_parse.py` `_skip_if_cached()`、`manifest.json` |
| **rpg-roleplay-platform** | 章节 splitter 丰富 | 扩充 `_split_text_into_chapters`：支持“第…章”、Markdown `#` 标题、数字点号（`1.`、`13、`）等多种章节头，兼容 `novel2gal` 七种 splitter 的规则思想 | `gal_parse.py` `_split_text_into_chapters` |

### 4.2 中期：架构融合——阶段化可恢复管线（下一迭代）

参考 `rpg-roleplay-platform` 的 branchable saves（commit/ref/checkout）与 `Story-to-game` 的审核锁思想，将 `gal` 扩展为可阶段化恢复的文游管线，保持文字游戏运行时作为最终交付形态之一。

**建议阶段划分（映射到 `GalPlayOrchestrator` / `GalParseOrchestrator` 的 `step_*`）：**

```
阶段 0: 权限门与项目初始化      → 记录 project-mode（私用/商业/公版）、输出目录骨架
阶段 1: 小说离线解构            → gal-parse 产出 worldbook/scenes/initial_state/manifest（已有）
阶段 2: 世界书审批门禁           → 新增 --approve-worldbook：人工确认角色/地点/物品/规则后，才初始化 GameState 并进入运行时
阶段 3: 初始状态锁定              → 确认起始地点、背包、在场角色、剧情标志
阶段 4: 运行时单回合执行          → gal-play runtime_turn + Python 显式应用 TurnResult（已有）
阶段 5: 滚动摘要与记忆预算        → summarize_history 按 token 预算滚动（已有）
阶段 6: 硬规则裁判（新增独立 agent）→ 独立校验 agent：scene_change 是否存在、inventory 是否合法、关系值 [-1,1]
阶段 7: 多回合运行时循环          → 每 N 回合 checkpoint 到 save.json；支持 --max-turns / --log 回放
阶段 8: 文游导出与发布            → 导出 save.json、滚动摘要、历史窗口、可选的文本剧本记录
```

**关键架构变更：**
- 编排器保留 `run()` 主流程，但每个 `step_xxx` 都可独立调用并留下检查点文件（参考 `rpg-roleplay-platform` 阶段状态与 `check_state.py` 模式）。
- 新增 `gal_tools.py`（按 AGENTS.md“为子命令添加工具”路径）：`ToolsMixin` + `_TOOL_PARAMS`，把阶段 2/6/8 等暴露为可被 LLM 工具循环调用的 `tool_*` 方法，实现开放工具调用循环。
- 新增 `gal_pmt.py` 中的 `VALIDATE_CHANGE_PMT`（裁判提示词）与 `gal_models.py` 中的 `ValidationResult` 模型。

### 4.3 长期：从文字游戏向多模态文游扩展（视需求，保持文字游戏运行时为核心真相源，不涉及视频）

若未来用户明确要求 `gal` 不只输出纯文本状态，还能产出多模态表现，可融合以下能力，但保持“文字游戏运行时”为核心真相源，**不涉及视频**：

| 能力 | 融入自 | 在 `gal` 中的体现（仅文游，不涉及视频） |
|---|---|---|
| **视觉圣经 / 角色一致性** | Kaleidoscope、Story-to-game | `worldbook.characters` 扩充 `visual_reference` 字段（外观硬描述、可选图片路径）；运行时叙事涉及角色时，LLM 必须引用世界书外观描述，禁止编造新特征；台词须符合 `voice` |
| **一格一张图 / 面板复合** | Kaleidoscope（ComfyUI）、AI-Game-From-Story（HTML5 表现层） | 文字游戏每回合的 `narration` 可进一步拆分为“面板指令”（panel intent），由外部图生图工具按面板出图，再本地合成页面；文字游戏状态继续由 Python 维护，图像仅为表现层，不与状态逻辑耦合 |
| **免费 / 无 GPU 后端** | AI-Game-From-Story（Ollama 本地降级） | `OpenAIClient` 可扩展支持本地/免费后端，降低单用户运行成本 |
| **Branchable saves** | rpg-roleplay-platform | `save.json` 增加版本分支，支持 checkout 到任意历史回合、分支存档，30 天优雅删除队列 |
| **向量检索长期记忆** | rpg-roleplay-platform、AI-Game-From-Story | 引入轻量向量库或本地降级，按情境向量检索历史片段注入提示词，补充滚动摘要 |

## 5. 优先级建议

1. **先做短期**：零依赖，直接提升 `gal` 的可用性与可审计性（硬规则裁判已有，可补强 `--validate`、章节 splitter 丰富、纯文本兜底）。
2. **再做中期**：阶段化检查点 + `gal_tools.py` 工具循环，使 `gal` 能“停下、人工核准、恢复继续”，像 `rpg-roleplay-platform` 的 branchable saves 一样可版本管理。
3. **最后做长期**：若用户明确要求多模态表现，再引入图像生成后端与面板合成，此时 `gal` 的 `GameState`/`TurnResult` 已成为多模态管线的“状态真相层”，图像仅为表现层，不与状态逻辑耦合。

## 6. 验收标准（只做文游）

- [ ] `novel-tool gal-parse --help` 与 `novel-tool gal-play --help` 显示任务书 §6 定义的全部参数。
- [ ] `gal-parse` 输入 ≥ 5 章 EPUB/txt，成功产出 `worldbook.json` / `scenes.json` / `initial_state.json` / `manifest.json`。
- [ ] 场景完整性：场景数 ≥ 章节数 × 4（3000 字/章基准）；抽样检查无大段情节被压缩成单场景。
- [ ] 角色卡可去重：跨章出现的同一角色在 `worldbook.characters` 中只出现一次（`PMT_MERGE_ENTITIES` 生效）。
- [ ] `gal-play` 加载资产包，`--script` 模式下自动跑 ≥ 20 轮，全程无异常退出、无状态非法（位置/物品/关系值均在合法域）。
- [ ] 存档 → 退出 → 读档 → 继续，`GameState` 与历史窗口一致；`assets_hash` 与 `manifest.json` 不一致时拒绝读档。
- [ ] 会话超过 token 预算时，`rolling_summary` 被更新，旧历史被折叠，游戏可继续 ≥ 20 轮。
- [ ] 非法 `scene_change`（世界书不存在的地点）或非法 `item_delta`（移除不存在的物品）被裁判拒绝并触发 LLM 重写；重试仍失败则降级为“仅叙事、不改状态”。
- [ ] 角色台词符合 `voice` 与 `knowledge_scope`，OOC 率 ≤ 10%（抽样 20 条台词）。
- [ ] `scene_change` 只在玩家显式移动时发生（抽样 10 次移动，误触发 ≤ 1）。
- [ ] 所有新增/修改代码通过 `python -m py_compile` 与 `pytest tests/test_gal.py` 全部通过；无硬编码密钥。
- [ ] 所有 LLM 调用经 `OpenAIClient`（含新增 `call_llm_structured`），无直接 `openai.OpenAI()` 散落调用。
- [ ] 缓存命中：同一章节重复 `gal-parse` 时，LLM 调用次数为 0（磁盘缓存生效）。
- [ ] `README.md` 中 `gal-parse`/`gal-play` 子命令章节已更新，且未出现任何视频/影片/音频相关表述。

## 7. 非目标（明确排除）

- 图形界面（首版）、Web 服务、多人游戏、网络同步。
- 多语言小说（首版只处理中文）。
- 复杂战斗/数值系统（首版以叙事 + 轻量状态为主）。
- 影片生成、视频编解码、音频/TTS、成片组装、时长量子。
- 任何与“影片”“视频”“动画”“音频”相关的产物或参数。

本任务书严格限定在**中文互动文游/文字游戏叙事引擎**范围内。
