# 任务书：新增 `cross-anls` 子命令（跨书拆解分析）

> 本任务书基于《BookerNovelTool 代码结构》描述的项目约定编写。目标：新增 `cross-anls` 子命令，扫描指定目录中的单书拆解结果（JSON / YAML），聚合为跨书素材库。保持与现有 `novel-anls`、`metrics` 等子命令一致的模块拆分与命名约定。

---

## 一、子命令规格

### 1.1 命令定义

| 项 | 值 |
|---|---|
| 子命令名 | `cross-anls` |
| 模块文件 | `BookerNovelTool/cross_anls.py` |
| CLI 入口函数 | `cross_anls(args)` |
| 注册函数 | `reg_subparser(subparsers)` |
| 编排器类 | `CrossAnlsOrchestrator` |
| Agent 类 | `CrossAnlsAgent`（`cross_anls_agent.py`） |
| 模板文件 | `cross_anls_pmt.py` |
| 模型文件 | `cross_anls_models.py` |

命名与现有约定对齐：`sub-cmd` ↔ `sub_cmd.py` ↔ `sub_cmd(args)` ↔ `reg_subparser(subparsers)`，参照 `novel-anls` 的模块拆分方式（orchestrator + agent + pmt + models 四文件）。

### 1.2 CLI 参数

```python
def reg_subparser(subparsers):
    parser = subparsers.add_parser(
        "cross-anls",
        help="跨书拆解分析：扫描目录中的单书拆解结果（JSON/YAML），聚合为跨书素材库",
    )
    parser.add_argument("dir", help="包含单书拆解结果（JSON/YAML）的目录")
    parser.add_argument("-o", "--output", default=None,
        help="输出文件路径（默认 <dir>/cross_book_analysis.json）")
    parser.add_argument("-t", "--threads", type=int, default=8,
        help="并行线程数")
    parser.add_argument("--min-books", type=int, default=2,
        help="最少书籍数，少于该值时仅警告不中断")
    parser.add_argument("--recursive", action="store_true",
        help="递归扫描子目录")
    parser.add_argument("--skip-tag-extraction", action="store_true",
        help="跳过标签提取（单书结果已含跨书标签字段时使用）")
    parser.add_argument("--focus-tags", nargs="+", default=["emotion_module_tags"],
        choices=["emotion_module_tags", "rhythm_pattern_tags",
                 "conflict_type_tags", "character_archetype_tags"],
        help="生成模式卡片的标签维度（默认仅情绪模块）")
    parser.set_defaults(func=cross_anls)
```

LLM 公共参数（`-m/--model`、`-k/--key`、`-H/--host`、`-tm/--temp`、`-retry` 等）由 `__main__.py` 顶层 parser 提供，子命令不重复定义。

### 1.3 输入与输出

| 项 | 规格 |
|---|---|
| 输入 | 目录路径；扫描 `*.json`、`*.yaml`、`*.yml`；可选递归 |
| 输入格式 | 单书拆解结果，兼容 `BookAnalysisReport` 结构（含 `book_meta`、`chapter_summaries`、`modules`） |
| 输出默认路径 | `<dir>/cross_book_analysis.json` |
| 输出格式 | JSON（`CrossBookAnalysisReport.model_dump(mode="json")`） |
| 输出排除 | 扫描时排除文件名匹配 `cross_book_analysis.*` 的文件，避免把输出当输入 |

### 4.2 `TAG_EXTRACT_PMT`

输入单书拆解结果（`book_meta` + 章节摘要精简 + 模块摘要），输出 `CrossBookComparableFields` 的标签子集与 `emotion_module_instances`。要求：

1. 每个标签字段从对应候选池中选择，可多选。
2. `emotion_module_instances` 每条含 `tag`、`description`（非原文）、`position`、`setup_chapters`、`payoff_chapter`、`aftermath_chapters`。
3. 无法判断的字段填 `null` 或 `[]`。

### 4.3 `PATTERN_CARD_PMT`

输入：`tag_dimension`、`tag_value`、该标签下所有书的变体实例列表（JSON）。输出 `PatternCard`。要求：

1. `pattern_definition` 四个子字段必须具体，不能空泛。
2. `stable_elements` 是所有变体共有的结构，`variable_elements` 是变体间可替换的参数。
3. `variant_axis` 列出变体之间的差异维度（如“释放时机”“反派强度”）。
4. `failure_modes` 从变体描述中归纳“用砸的典型方式”，若无则空列表。

### 4.4 `LINEAGE_PMT`

输入全部 `PatternCard` 的精简列表（`pattern_card_id`、`pattern_name`、`tag_value`、`stable_elements`、`variable_elements`）。输出 `PatternLineage` 列表。要求：只输出确实存在演化/冲突/互补关系的配对，不强行凑关系。

### 4.5 `COMPARISON_MATRIX_PMT`

输入全部 `CrossBookComparableFields` 的数值字段与标签字段。输出 `ComparisonMatrix` 列表，覆盖至少：节奏密度、铺垫效率、对话占比、开篇类型分布、结构模型分布。

### 4.6 `REUSE_RECOMMENDATION_PMT`

输入 `PatternCard` 精简列表 + `ComparisonMatrix`。输出 `ReuseRecommendation` 列表，按“写新书的场景”组织（开篇、升级段、转折段、收尾段）。

## 六、Orchestrator（`cross_anls.py`）

### 6.1 类结构与阶段划分

```python
class CrossAnlsOrchestrator:
    def __init__(self, args):
        self.args = args
        self.input_dir = args.dir
        self.output_path = args.output or path.join(args.dir, "cross_book_analysis.json")
        self.max_workers = args.threads
        self.agent = CrossAnlsAgent(args)
        self.loaded_books: List[LoadedBookInfo] = []
        self.skipped_books: List[SkippedBookInfo] = []
        self.book_reports: List[Dict[str, Any]] = []
        self.comparable_fields: List[CrossBookComparableFields] = []
        self.pattern_cards: List[PatternCard] = []
        self.lineages: List[PatternLineage] = []
        self.matrix: List[ComparisonMatrix] = []
        self.recommendations: List[ReuseRecommendation] = []
```

### 6.2 阶段一：扫描与加载

- 扫描 `args.dir`，匹配 `*.json` / `*.yaml` / `*.yml`；`--recursive` 时递归。
- 排除输出文件（文件名匹配 `cross_book_analysis.*`）。
- 逐个尝试加载：JSON 用 `json.load`，YAML 用 `util.read_yaml_model` 或 `yaml.safe_load`。
- 校验：必须含 `book_meta` 或 `chapter_summaries` 之一；否则记入 `skipped_books`。
- 派生 `source_book_id`：优先读文件中已有的 `source_book_id`；否则用 `md5(f"{book_title}|{author}")[:12]`。
- 记录 `LoadedBookInfo`，收集 `book_reports`。
- 若 `len(loaded_books) < args.min_books`，`logger.warning` 但不中断。

### 6.3 阶段二：逐书标签提取（并行）

- 若 `--skip-tag-extraction`，跳过本阶段，直接从 `book_reports` 中读取 `comparable_fields`（若存在）。
- 否则用 `ThreadPoolExecutor` 并行调用 `agent.extract_tags`，并发数 `args.threads`。
- 每本书调用后**立即**用程序补充结构化数值字段（`climax_interval_distribution`、`setup_payoff_ratio`、`dialogue_description_ratio`、`sentence_rhythm_profile`、`sensory_bias`），从 `chapter_summaries` 和 `modules` 中计算，不依赖 LLM。
- 单本失败记入日志，`comparable_fields` 中该书的标签字段留空，但数值字段仍保留，不阻断后续聚合。

### 6.4 阶段三：模式卡片生成（并行，按 `--focus-tags`）

- 对 `args.focus_tags` 中的每个维度，按 `tag_value` 分组：每组收集各书 `emotion_module_instances`（或对应维度的变体）中匹配该 tag 的实例。
- 只对变体数 ≥ 2 的组生成模式卡片（单样本无法归纳模式）。
- 用线程池并行调用 `agent.generate_pattern_card`，每组一次调用。
- 生成失败记录日志并跳过该组。
- `pattern_card_id` 格式：`{tag_dimension}_{tag_value}_{序号}`，序号在组内递增。

### 6.5 阶段四：谱系 + 对比矩阵 + 复用建议（串行）

- `agent.analyze_lineages(cards)` → `self.lineages`
- `agent.build_comparison_matrix(fields)` → `self.matrix`
- `agent.generate_reuse_recommendations(cards, matrix)` → `self.recommendations`
- 质量基线用程序计算（对 `comparison_matrix` 中各数值维度求 median / p25 / p75），不调 LLM。

### 6.6 阶段五：组装与保存

- 组装 `CrossBookDatasetMeta`：`book_count`、`total_chapters`、`books_loaded`、`books_skipped`、`genre_distribution`（按 `genre_tags` 统计）、`tag_coverage`（各标签维度出现次数）、`generated_at`（ISO 时间）。
- 组装 `CrossBookAnalysisReport`，`json.dump(..., ensure_ascii=False, indent=2)` 写入 `self.output_path`。
- 日志打印摘要：加载书数、跳过书数、模式卡片数、谱系数、矩阵维度数、建议数。

### 6.7 `cross_anls(args)` 入口

```python
def cross_anls(args):
    orchestrator = CrossAnlsOrchestrator(args)
    orchestrator.run()
```

`run()` 依次执行阶段一至五；目录不存在时 `logger.fatal` 并返回。

## 八、实施顺序

1. **建模型**：`cross_anls_models.py` 全部 Pydantic 模型。
2. **建模板**：`cross_anls_pmt.py` 候选池常量 + 5 个模板 + 系统提示词。
3. **建 Agent**：`cross_anls_agent.py`，`_call` 与 `NovelAnlsAgent._call` 同构。
4. **建 Orchestrator**：`cross_anls.py`，先实现阶段一（扫描加载）和阶段五（保存），跑通空壳流程。
5. **补阶段二**：标签提取 + 程序数值补充。
6. **补阶段三**：模式卡片生成。
7. **补阶段四**：谱系、矩阵、建议、质量基线。
8. **注册**：`__main__.py` 加 `cross_anls.reg_subparser`。
9. **联调**：用两本已拆解的书跑端到端，检查输出 JSON 结构。

## 九、验收标准

| 维度 | 标准 |
|---|---|
| 子命令可用 | `BookerNovelTool cross-anls <dir>` 能执行；`--help` 显示全部参数 |
| 项目一致性 | 文件命名、`reg_subparser` + `args.func(args)` 派发方式与 `novel-anls` 一致 |
| 输入兼容 | 同时支持 `.json`、`.yaml`、`.yml`；无效文件记入 `books_skipped` 不中断 |
| 输出路径 | 默认 `<dir>/cross_book_analysis.json`；`-o` 可覆盖；输出文件不被下次扫描当作输入 |
| 标签提取 | 每本书产出 `CrossBookComparableFields`，标签值来自候选池；`--skip-tag-extraction` 时跳过 LLM 调用 |
| 数值字段 | `climax_interval_distribution`、`setup_payoff_ratio`、`dialogue_description_ratio` 等由程序计算，不依赖 LLM |
| 模式卡片 | 只对变体数 ≥ 2 的 tag 生成；`stable_elements` 与 `variable_elements` 非空；`pattern_card_id` 唯一 |
| 容错 | 单本书标签提取失败、单组模式卡片生成失败均不中断全流程；日志记录 `books_skipped` 与失败原因 |
| 输出完整性 | `CrossBookAnalysisReport` 含 `dataset_meta`、`comparable_fields`、`pattern_cards`、`pattern_lineages`、`comparison_matrix`、`reuse_recommendations`、`quality_baseline` 全部字段 |
| 花括号 | 所有 prompt 中 JSON 示例的花括号为 `{{ }}`，占位符为 `{xxx}` |
| 最少书籍 | `book_count < min_books` 时仅警告，仍继续执行 |

## 十、风险与边界

1. **V1 范围收窄**：默认只对 `emotion_module_tags` 生成完整模式卡片；`rhythm_pattern_tags`、`conflict_type_tags`、`character_archetype_tags` 通过 `--focus-tags` 显式开启。避免首版 LLM 调用爆炸。
2. **单书结果缺标签字段**：当前 `novel-anls` 尚未输出跨书标签，跨书命令必须自己调 LLM 提取。若未来单书阶段已输出标签，`--skip-tag-extraction` 可直接复用，节省成本。
3. **LLM 调用次数估算**：`N` 本书（标签提取）+ `M` 个有效 tag 组（模式卡片）+ 3 次串行调用（谱系/矩阵/建议）。`N` 与 `M` 都随样本增长，建议 V1 用 2–5 本书验证流程，再扩量。
4. **模式卡片质量依赖变体描述**：若 `emotion_module_instances` 的 `description` 过于空泛，归纳出的 `stable_elements` 会失真。`TAG_EXTRACT_PMT` 中要强调“描述具体写法，不写抽象评价”。
5. **`source_book_id` 冲突**：同名同作者不同版本会生成同一 ID。V1 接受此风险，在 `LoadedBookInfo` 中保留 `file_path` 用于区分；V2 可引入 `source_edition` 参与 ID 计算。
6. **不做的事**：本任务书不修改 `novel_anls.py`、`novel_anls_agent.py`、`novel_anls_pmt.py`、`novel_anls_models.py`；不建向量库；不做跨书 RAG 检索。跨书素材库的输出结构为后续检索层预留字段（`pattern_card_id`、`variant_id`），但检索功能不在本次范围。
7. **输出文件可重复运行**：同一目录重复运行会覆盖默认输出文件；若需版本化，用户可用 `-o` 指定带时间戳的文件名。
