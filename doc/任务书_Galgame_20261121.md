# BookerNovelTool `gal` 子命令任务书

## 1. 背景与目标

在 BookerNovelTool 中新增 `gal` 能力：**把一部小说（EPUB/纯文本）离线解构为结构化游戏资产，再通过一个状态化运行时引擎，用 OpenAI API 驱动可交互的中文文字游戏**。完全复用项目现有的 `OpenAIClient`、`render_prompt`、Pydantic 模型与 YAML/JSON 持久化基础设施。

设计原则（与现有模块保持一致）：

- **职责分离**：LLM 只负责“生成叙事”和“抽取结构化信息”，世界真实状态由 Python 侧状态机维护，绝不依赖 LLM 记忆。
- **离线/在线分离**：解析阶段一次性产出资产包；运行阶段只读资产包 + 状态，按轮调用 LLM。
- **可观测可调试**：每个阶段都有结构化中间产物落盘，失败可单独重跑。
- **复用优先**：不重复实现 EPUB 解析、LLM 重试、缓存、提示词渲染。

## 2. 范围

**包含：**

- `gal-parse`：小说 → 游戏资产包（worldbook / scenes / 初始状态）
- `gal-play`：加载资产包，进入交互式文字游戏（CLI REPL，可选 rich TUI）
- 结构化输出（`response_format` / Pydantic parse）的客户端支持
- 记忆预算管理与滚动摘要
- 存档/读档（JSON）

**不包含（首版）：**

- 图形界面、Web 服务
- 多人游戏、网络同步
- 多语言小说（首版只处理中文）
- 复杂战斗/数值系统（首版以叙事 + 轻量状态为主）

## 3. 模块与文件结构

遵循项目约定：`sub-cmd` ↔ `sub_cmd.py`，共享逻辑放平行文件（与 `novel_anls` 模式一致）。

```
BookerNovelTool/
├── gal_parse.py          # gal-parse 子命令：GalParseOrchestrator + reg_subparser + CLI 入口
├── gal_play.py           # gal-play 子命令：GalPlayOrchestrator + reg_subparser + CLI 入口
├── gal_agent.py          # GalParseAgent / GalRuntimeAgent：封装 LLM 调用（复用 OpenAIClient）
├── gal_engine.py         # GameEngine：状态机、记忆组装、回合循环（纯 Python，不直接调 LLM）
├── gal_models.py         # Pydantic：WorldBook / CharacterCard / Scene / GameState / TurnResult / SummaryResult
├── gal_pmt.py            # 提示词常量与 render_prompt 调用封装
└── （可选）gal/          # 若文件超过 6 个再迁为子包，首版不建
```

`__main__.py` 中新增两行注册：

```python
from .gal_parse import reg_subparser as reg_gal_parse
from .gal_play import reg_subparser as reg_gal_play
reg_gal_parse(subparsers)
reg_gal_play(subparsers)
```

**为何拆两个子命令而非 `gal --mode`**：与项目现有“一命令一模块”约定一致；解析与运行的生命周期、参数集、失败模式完全不同，拆开更清晰。共享代码全部下沉到 `gal_engine.py` / `gal_models.py` / `gal_agent.py`。

## 4. 数据结构（`gal_models.py`，Pydantic v2）

### 4.1 离线资产

```python
class Relationship(BaseModel):
    target_id: str
    relation: str            # TRUSTS / FEARS / ALLY_OF / OPPOSES / WORKS_FOR ...
    strength: float          # [-1, 1]

class CharacterCard(BaseModel):
    id: str                  # char_001
    name: str
    role: Literal["protagonist", "supporting", "antagonist", "npc"]
    description: str
    traits: list[str]
    voice: str               # 说话风格样本（2-3 句原文台词）
    knowledge_scope: list[str]   # 该角色“可能知道”的信息标签
    relationships: list[Relationship]

class Location(BaseModel):
    id: str                  # loc_001
    name: str
    description: str
    connections: list[str]   # 可达地点 id
    items: list[str]

class SceneElement(BaseModel):
    type: Literal["action", "dialogue", "transition", "reveal"]
    content: str
    speaker_id: str | None = None
    emotion: str | None = None

class Scene(BaseModel):
    scene_number: int
    chapter: int
    location_id: str
    characters_present: list[str]
    elements: list[SceneElement]
    is_flashback: bool = False

class WorldBook(BaseModel):
    title: str
    source_hash: str         # md5，用于缓存/增量
    characters: list[CharacterCard]
    locations: list[Location]
    rules: list[str]         # 世界硬规则（“此门需钥匙”）
    factions: list[str] = []

class AssetsBundle(BaseModel):
    worldbook: WorldBook
    scenes: list[Scene]
    initial_state: "GameState"
```

### 4.2 运行时状态

```python
class GameState(BaseModel):
    player_location: str
    inventory: list[str]
    flags: dict[str, bool | int | str]     # 剧情标志
    relationships: dict[str, float]        # char_id -> strength 覆盖值
    turn: int
    rolling_summary: str                   # 滚动摘要
    present_characters: list[str]
    game_over: bool = False

class TurnResult(BaseModel):
    narration: str                         # 面向玩家的叙事
    dialogue: list[dict] = []              # [{"speaker_id":..., "line":..., "emotion":...}]
    scene_change: str | None = None        # 新 location_id
    item_delta: dict | None = None         # {"add": [...], "remove": [...]}
    relationship_delta: list[dict] | None = None
    flag_update: dict | None = None
    game_over: bool = False

class SummaryResult(BaseModel):
    summary: str                           # 1-3 句累积摘要
```

### 4.3 存档

`SaveFile` = `GameState` + `history_window`（最近 K 轮逐字）+ `assets_hash`（校验资产包版本一致）。

## 5. 提示词资产（`gal_pmt.py`）

每条提示词独立成常量（或首版内联字符串 + `render_prompt` 渲染），命名 `PMT_<阶段>`。**所有抽取类调用必须带 `response_format`（JSON 或 Pydantic schema）**。

| 常量 | 阶段 | 温度 | 职责 |
| :--- | :--- | :--- | :--- |
| `PMT_EXTRACT_CHARACTERS` | parse | 0.2 | 章节 → 角色卡 + 关系 |
| `PMT_EXTRACT_SCENES` | parse | 0.2 | 章节 → 场景列表（强完整性规则） |
| `PMT_EXTRACT_LOCATIONS` | parse | 0.2 | 章节 → 地点与连接 |
| `PMT_MERGE_ENTITIES` | parse | 0.1 | 跨章去重合并角色/地点 |
| `PMT_RUNTIME_DIRECTOR` | play | 0.7 | 导演 + 声音，输出 `TurnResult` |
| `PMT_RUNTIME_SUMMARY` | play | 0.3 | 滚动摘要压缩 |
| `PMT_NPC_GRAPH` | play | 0.3 | 关系图谱增量更新（可选，后置到 M3） |

**关键提示词要求（必须写进任务验收）：**

- **完整性对抗**：场景抽取提示词必须包含“决不遗漏”“每一段对话=一个场景”“3000 字至少 4 个场景”及自检语句，对抗 LLM 摘要倾向。
- **闪回不压缩**：`is_flashback=true` 的场景必须完整展开。
- **运行时最小变化**：导演提示词必须声明“本回合世界变化应尽可能小，只在必要时设置 `scene_change`”。
- **角色知识边界**：导演提示词要求角色只知道 `knowledge_scope` 覆盖的信息。
- **输出唯一 JSON**：运行时提示词末尾强调“只输出一个 JSON 对象，不要任何额外文本”。

## 6. CLI 设计

复用 `__main__.py` 已有的 LLM 公共参数（`-m/-k/-H/-tm/-retry/--emb`），只追加业务参数。

### 6.1 `gal-parse`

```
booker gal-parse <input> -o <assets_dir>
    # 必填
    <input>                      EPUB 或 .txt 小说路径
    -o/--out <dir>               资产包输出目录（写 worldbook.json / scenes.json / initial_state.json）

    # 业务可选
    -c/--chapters <range>        章节范围，如 1-5；默认全部
    --max-chars <int>            单章截断长度，默认 12000
    --skip-existing              资产包已存在则跳过（按 source_hash 判定）
    --concurrency <int>          章节并发解析数，默认 4
    --no-merge                   跳过实体合并（调试用）
```

输出：`assets_dir/` 下三个 JSON 文件 + `manifest.json`（含 `source_hash`、模型、时间戳）。

### 6.2 `gal-play`

```
booker gal-play <assets_dir>
    -s/--save <path>             存档路径（不存在则新建；存在则读档继续）
    --ui {plain,rich}            默认 plain，rich 为可选增强
    --max-turns <int>            自动跑 N 轮后退出（用于测试）
    --script <path>              脚本模式：逐行读取玩家输入（测试/回放用）
    --log <path>                 将每轮 TurnResult 追加写入 JSONL
```

进入 REPL 后支持元命令：`/save`、`/load`、`/state`、`/quit`、`/help`。

## 7. 运行时引擎设计（`gal_engine.py`）

**核心循环（纯 Python，LLM 调用委托给 `gal_agent.py`）：**

```
load assets + save
loop:
  1. agent.direct(player_input, assembled_context) -> TurnResult
  2. engine.apply(TurnResult)  # 显式更新 GameState
  3. engine.append_history(turn, player_input)
  4. if history_tokens > budget: agent.summarize() -> SummaryResult; 折叠旧历史
  5. render(narration, dialogue)
```

**记忆预算组装（每轮）：**

1. `rolling_summary`（始终全量）
2. 当前地点 + 在场角色卡（全量）
3. 最近 K 轮逐字对话（从新到旧填充，直到 token 预算耗尽）
4. 当前 `GameState` 摘要（位置、背包、标志、关系）
5. 玩家新输入

token 估算用 `tiktoken`（若项目未依赖则加；或先用 `len(text)//2` 近似，任务书建议加 `tiktoken`）。

**状态更新规则（硬编码在 Python，不经 LLM）：**

- `scene_change` → 必须校验目标 `location_id` 存在于 `worldbook.locations`，否则丢弃并记 warning。
- `item_delta` → 校验物品在当前地点 `items` 或背包中，非法操作丢弃。
- `relationship_delta` → 裁剪到 `[-1, 1]`。
- 任何 `TurnResult` 字段非法 → 触发一次重试（换温度或加“修正”提示），仍失败则降级为“仅叙事、不改状态”。

**存档**：每次 `/save` 或退出时写入 `SaveFile`；`assets_hash` 与 `manifest.json` 不一致时拒绝读档。

## 8. 与现有基础设施集成点

| 现有设施 | 在 gal 中的用法 |
| :--- | :--- |
| `openai.OpenAIClient` / `call_llm_retry` | 所有 LLM 调用入口；**需扩展**：新增 `call_llm_structured(messages, schema: type[BaseModel], ...)`，内部走 `client.beta.chat.completions.parse`，并接入项目已有的磁盘/进程内缓存（复用 `metrics/agent.py` 的缓存 key 策略：`md5(model + prompt + temperature)`） |
| `util.render_prompt` | 渲染 `gal_pmt.py` 中的模板 |
| `util.json_dump_model` / `read_yaml_model` / `write_yaml_model` | 资产包与存档的序列化（统一用 JSON，便于跨语言；YAML 仅用于 manifest 可读性） |
| `util.md5` | `source_hash`、缓存 key、存档版本校验 |
| `metrics/common.Budget` | 运行时 token 预算可直接复用 |
| `novel_anls` 的 EPUB 解析 | **复用**：`gal-parse` 的 EPUB 拆章直接调用 `novel_anls` 已有的拆章函数，不重复实现 |
| `pyproject.toml` | 新增可选依赖：`rich`（TUI）、`tiktoken`（预算），均为 optional extras |

**必须新增的 `OpenAIClient` 能力**（任务书列为 M0 前置）：

- `call_llm_structured(...)`：支持 `response_format=PydanticModel`，返回 `parsed` 对象。
- 缓存层：与 `MetricsAgent` 一致的磁盘缓存，key 含 model + prompt hash + temperature。

## 9. 验收标准

**功能验收：**

1. 输入一本 ≥ 5 章的 EPUB，`gal-parse` 成功产出 `worldbook.json` / `scenes.json` / `initial_state.json` / `manifest.json`。
2. 场景完整性：**场景数 ≥ 章节数 × 4**（3000 字/章基准）；抽样检查无大段情节被压缩成单场景。
3. 角色卡可去重：跨章出现的同一角色在 `worldbook.characters` 中只出现一次（`PMT_MERGE_ENTITIES` 生效）。
4. `gal-play` 加载资产包，能在 `--script` 模式下自动跑 ≥ 20 轮，全程无异常退出、无状态非法（位置/物品/关系值均在合法域）。
5. 存档 → 退出 → 读档 → 继续，`GameState` 与历史窗口一致。
6. 会话超过 token 预算时，`rolling_summary` 被更新，旧历史被折叠，游戏可继续 ≥ 20 轮。

**质量验收（人工抽样，10 轮）：**

- 角色台词符合 `voice` 与 `knowledge_scope`，无明显 OOC（抽样 20 条台词，OOC 率 ≤ 10%）。
- 叙事与 `GameState` 无矛盾（位置、在场角色、背包）。
- `scene_change` 只在玩家显式移动时发生（抽样 10 次移动，误触发 ≤ 1）。

**工程验收：**

- 新增代码通过 `ruff`/`pytest`（若项目已配置）；无硬编码密钥。
- 所有 LLM 调用经 `OpenAIClient`，无直接 `openai.OpenAI()` 散落调用。
- 缓存命中：同一章节重复 `gal-parse` 时，LLM 调用次数为 0（磁盘缓存生效）。

## 11. 风险与缓解

| 风险 | 缓解 |
| :--- | :--- |
| LLM 抽取“摘要化”，场景缺失 | 提示词强完整性规则 + 场景数下限校验 + 失败重试时追加“你遗漏了情节，请补全” |
| 结构化输出不稳定（旧模型/兼容 host） | `call_llm_structured` 失败时降级到 `json_object` + Pydantic 手动校验 + 一次修正重试 |
| 运行时状态被 LLM 幻觉污染 | 状态变更全部经 Python 校验；非法字段丢弃并记 warning，不进 `GameState` |
| 长对话超上下文 | 分层记忆预算 + 滚动摘要；`--max-turns` 用于测试预算路径 |
| 与现有 `novel_anls` EPUB 解析耦合 | 只调用其稳定拆章函数；若接口不稳，在 `gal_parse.py` 内做薄适配层 |
| 中文 token 估算偏差 | 引入 `tiktoken`，预算阈值留 20% 余量 |
