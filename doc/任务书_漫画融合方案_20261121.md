# 任务书：BookerNovelTool `comic` 子命令漫画融合方案

版本：1.0
日期：2026-11-21
适用仓库：D:\src\BookerNovelTool
子命令：`comic`（BookerNovelTool/comic.py）

---

## 1. 背景与目标

本仓库已实现 `comic` 子命令，将小说文本离线抽取为文字游戏资产（世界书：角色/地点/物品/规则 + 初始状态），再进入状态化对话式运行时，玩家输入行动，LLM 以角色口吻叙事，Python 侧严格维护世界状态（位置、背包、关系、标志）。

本任务书的目标是：**将 `../novel2comic/` 中四个漫画项目的成熟工程实践融入 `comic` 子命令，使其从“最小可运行原型”演进为可生产、可审计、可恢复的漫画叙事引擎。**

**明确界限：只做漫画，不做视频。** 所有涉及影片生成、音频、H3/FreeVideo/remix/ref2va、成片组装、时长量子等视频相关内容均不在本方案范围内。融合对象仅限四项目中的“漫画/文字规划/资产/审核/可恢复管线”部分。

## 4. 融合方案（只做漫画，不做视频）

方案分三个层次，全部围绕“漫画叙事引擎”展开，不涉及影片/音频/视频组装。

### 4.1 短期：可直接落地到 `comic` 子命令（本周内，零依赖）

| 融入来源 | 改进点 | 在 `comic` 中的具体做法 | 涉及文件 |
|---|---|---|---|
| **codex-novel-to-comic-studio** | 资产审批门禁 | 新增 `--approve-worldbook` 标志。默认抽取后进入运行时；若设置，则暂停于 `worldbook.json` 生成，要求人工确认后才初始化 `GameState` 并进入运行时。 | `comic.py` `reg_subparser` 新增 `--approve-worldbook` |
| **ai-comic-drama** | 输入指纹与缓存失效 | YAML 缓存文件名已用 `gen_objs_md5(ctx)`，追加 `md5(novel_text)` 到缓存键；若小说文本变更，缓存自动失效（上游改下游失效）。 | `comic_agent.py` `_call_json` 缓存键追加 `md5(novel_text)` |
| **inkstone** | 可恢复运行时 | `final_state.json` 已保存。新增 `--resume` 参数：读取 `final_state.json` 与 `worldbook.json`，继续上一局的 `GameState` 和滚动摘要，而非从头开始。 | `comic.py` `step_init_state` 支持从 `final_state.json` 恢复 |
| **text2comics** | 严格验证与回填 | `WorldChange` 解析失败已走 `json_repair` + `parse_obj_as`；新增硬规则裁判：若 `scene_change` 指向世界书中不存在的地点，或 `inventory_delta` 移除不存在的物品，拒绝并要求 LLM 重写。 | `comic_agent.py` `runtime_turn` 增加 `validate_change()` 硬规则校验 |
| **ai-comic-drama** | 审核锁状态机 | 轻量状态文件 `comic-state.json` 记录 `extracted / state_initialized / turn_N / finished`，每步只给一条下一步指令（`h3d next` 风格）。 | `comic.py` 新增 `_write_state_marker()` / `read_state_marker()` |

### 4.2 中期：架构融合——阶段化可恢复管线（下一迭代）

参考 codex-novel-to-comic-studio 的十阶段与 ai-comic-drama 的审核锁，将 `comic` 扩展为可阶段化恢复的漫画叙事管线，保持文字游戏运行时作为最终交付形态之一。

**建议阶段划分（映射到 `ComicOrchestrator.step_*`）：**

```
阶段 0: 权限门与项目初始化      → 记录 project-mode（私用/商业/公版）、输出目录骨架
阶段 1: 小说离线解构            → extract_assets() 产出 worldbook.json / initial_state.json（已有）
阶段 2: 世界书审批门禁           → 人工确认角色/地点/物品/规则，生成 WORLDBOOK_APPROVED 标记
阶段 3: 初始状态锁定              → 确认起始地点、背包、在场角色、剧情标志
阶段 4: 运行时单回合执行          → runtime_turn() + Python 显式应用 WorldChange（已有）
阶段 5: 滚动摘要与记忆预算        → summarize_history() 按 token 预算滚动（已有）
阶段 6: 硬规则裁判（新增）        → 独立校验 agent：scene_change 是否存在、inventory 是否合法、关系值是否越界 [-1,1]
阶段 7: 多回合运行时循环          → step_run_game() 循环，每 N 回合 checkpoint 到 final_state.json
阶段 8: 漫画导出与发布            → 导出 final_state.json、滚动摘要、可选的文本剧本记录
```

**关键架构变更：**
- 编排器 `ComicOrchestrator` 保留 `run()` 主流程，但每个 `step_xxx` 都可独立调用并留下检查点文件（参考 `check_state.py` 模式）。
- 新增 `comic_tools.py`（按 AGENTS.md“为子命令添加工具”路径）：`ToolsMixin` + `_TOOL_PARAMS`，把阶段 2/6/8 等暴露为可被 LLM 工具循环调用的 `tool_*` 方法，实现开放工具调用循环。
- 新增 `comic_pmt.py` 中的 `VALIDATE_CHANGE_PMT`（裁判提示词）与 `comic_models.py` 中的 `ValidationResult` 模型。

### 4.3 长期：从文字游戏向多模态漫画扩展（视需求，仅漫画）

若未来希望 `comic` 不只输出纯文本状态，还能产出漫画页面，可融合以下能力，但保持“文字游戏运行时”为核心真相源，**不涉及视频**：

| 能力 | 融入自 | 在 `comic` 中的体现（仅漫画） |
|---|---|---|
| **视觉圣经 / 角色一致性** | codex-novel-to-comic-studio、text2comics | `worldbook.characters` 扩充 `visual_reference` 字段（角色卡图片路径、外观硬描述）；运行时叙事涉及角色时，LLM 必须引用世界书中的外观描述，禁止编造新特征。 |
| **一格一张图 / 面板复合** | inkstone、text2comics | 文字游戏每回合的 `narration` 可进一步拆分为“面板指令”（panel intent），由外部图生图工具（ComfyUI / Agnes / Codex image2）按面板出图，再用 Pillow 本地合成漫画页面；文字游戏状态继续由 Python 维护，图像只是表现层。 |
| **台词不进生图提示词** | text2comics | 若扩展到图像生成，对话/旁白统一由嵌字程序叠加，LLM 出图提示词只含画面描述，避免文字跑进画面。 |
| **免费 / 无 GPU 后端** | inkstone | `OpenAIClient` 可扩展支持 Agnes 免费 API，降低单用户运行成本。 |
| **PDF / CBZ 绑定** | codex、inkstone、text2comics | 将运行时产生的 `narration` 序列与（可选）生成的页面图片，绑定为可阅读的数字漫画 / 游戏剧本 PDF。 |

## 5. 优先级建议

1. **先做短期**：`--resume`、`--approve-worldbook`、硬规则裁判 `validate_change()`、缓存输入指纹。四项零依赖，直接提升 `comic` 的可用性与可审计性。
2. **再做中期**：阶段化检查点 + `comic_tools.py` 工具循环，使 `comic` 能像 codex-novel-to-comic-studio 一样“中途停下、人工核准、恢复继续”。
3. **最后做长期**：若用户明确要求漫画页面输出，再引入图像生成后端与面板合成，此时 `comic` 的 `GameState`/`WorldChange` 已成为多模态管线的“状态真相层”，图像仅为表现层，不与状态逻辑耦合。

## 6. 验收标准（只做漫画）

- [ ] `novel-tool comic --help` 显示 `--resume`、`--approve-worldbook` 等新增参数。
- [ ] `novel-tool comic book.txt --extract-only` 仅生成 `worldbook.json`、`initial_state.json`，不进入运行时。
- [ ] `novel-tool comic book.txt --approve-worldbook` 在 `worldbook.json` 生成后暂停，等待人工确认后方进入运行时。
- [ ] `novel-tool comic book.txt --resume` 能从 `final_state.json` 恢复上一局状态并继续。
- [ ] `WorldChange` 中非法的 `scene_change`（世界书不存在的地点）或非法的 `inventory_delta`（移除不存在的物品）被裁判拒绝并触发 LLM 重写。
- [ ] 所有新增/修改代码通过 `python -m py_compile` 与现有集成测试（不引入视频相关依赖）。
- [ ] 文档 `README.md` 中 `comic` 子命令章节更新，且未出现任何视频/影片/音频相关表述。
